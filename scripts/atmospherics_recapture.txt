alias sensor_800              d0   # Gas Sensor, shared room - SAME physical device as GS-601/sensor_600 in atmospherics_regulation.ic10, wired here on a second cable, not a separate unit
alias recyclePump_800         d1   # Volume Pump, pulls room air into the filtration manifold
alias filtrationCO2_800       d2   # Filtration unit, CO2 filter only - recovered CO2 -> Area 400 TK-401
alias filtrationPollutant_800 d3   # Filtration unit, Pollutant filter - captured gas -> Pollutant storage tank
alias filtrationMethaneH2_800 d4   # Filtration unit, BOTH Methane and Hydrogen cartridges loaded - captured gas -> combined Methane/Hydrogen mix tank

# Every gas this loop touches goes to a tank now, not back into the room - the only thing
# that ever adds gas to the room atmosphere is Regulation's three pumps (atmospherics_
# regulation.ic10). That's why there's no "remainder" path here anymore: whatever this pump
# pulls in gets fully sorted - O2, CO2, and N2 each to their own supply tank; Pollutant to
# its own storage tank; Methane and Hydrogen together into one mix tank.
#
# "Volatiles" was renamed to "Methane" in a game update - same gas, RatioVolatiles is now
# RatioMethane. Hydrogen is a genuinely separate gas type, not part of Methane/Volatiles -
# it wasn't handled anywhere in this build before (the old Electrolyzer just vented its H2
# byproduct to exterior, and that housing is gone now).
#
# filtrationMethaneH2_800 is ONE Filtration unit with both a Methane filter and a Hydrogen
# filter cartridge loaded - multiple cartridges in the same unit mix their catch together,
# which is exactly what's wanted here since both go to the same mix tank anyway. This is
# a safety contingency: Volatile Ice melts into Methane + Hydrogen if it ends up inside the
# base (hauled in, dropped, whatever), and neither gas belongs in the room atmosphere.
# Ryan's rule: any Pollutant, Methane, or Hydrogen reading at all should trigger scrubbing
# until it's filtered out - same bare-presence pattern already used for Pollutant. Each
# filter only turns on for its own gas(es) being present, not just because the pump happens
# to be running for some other reason.
#
# O2 is controlled by a companion housing (atmospherics_recapture_riders.ic10), not this one
# - one IC housing only has 6 pins and this loop needs 7 devices (sensor, pump, and 5
# filters), so it's split in two. O2 has no trigger of its own; its filter just mirrors this
# housing's recyclePump_800 On state, riding along opportunistically whenever the pump is on
# for any reason, since O2 is a wanted gas, not "gas that isn't wanted" like
# Pollutant/Methane/Hydrogen.
#
# N2's Filtration unit also lives on the rider housing (filtrationN2_800r) and also just
# mirrors the pump's On state - but as of 2026-08-09 N2 DOES get a real trigger, computed
# right here even though the device that acts on it is on the other housing. Ryan found the
# room sitting at ~80% N2 (vs. the 60% target) with nothing anywhere in this build actively
# skimming an N2 surplus back down: Regulation only ever ADDS N2 (stops once at target, never
# removes), and this housing previously only ever ran the pump for CO2 excess or
# contamination - a pure N2 surplus with nothing else active just sat there unrecaptured
# indefinitely. Fixed by giving N2 the same excess-hysteresis treatment CO2 already has
# below, folded into the pump's own trigger set - once the pump turns on for N2 excess, the
# rider housing's existing "mirror the pump" logic for filtrationN2_800r picks it up
# automatically, no change needed on that housing at all.
#
# CO2 keeps its hysteresis band, same as before - CO2 belongs in the room mix at 20%, only
# the excess above target gets skimmed. N2's new band works the same way, using the same
# 60/58 target/low Regulation's own N2_TARGET/N2_LOW use, so the two subsystems agree on
# where the equilibrium sits - Regulation stops adding at 60, Recapture starts skimming above
# 60, both settle back to inactive between 58 and 60. Pollutant, Methane, and Hydrogen still
# have no target at all - no "acceptable" amount of any of them, so those trigger on bare
# presence (ratio > 0), no hysteresis band to hover near.
#
# N2's hysteresis memory (r12 below) is a bare register, not a device's own On state, unlike
# every other hysteresis check in this build - the device that actually acts on this trigger
# (filtrationN2_800r) lives on the rider housing and isn't wired to any pin here, so there's
# no local device state to read back. Registers persist across yield/j main loop iterations
# same as any other IC10 program, so r12 works fine as this housing's own memory of whether
# N2 was in its "on" phase last tick.
#
# Every alias in this build is suffixed by area number (_100, _200, etc.) - all IC housings
# share one network, so alias names need to be globally unique, not just unique within a
# single script. This housing gets "_800"; its companion (atmospherics_recapture_riders.ic10)
# gets "_800r".
define CO2_HIGH 20
define CO2_LOW  19

define N2_HIGH 60
define N2_LOW  58

main:
yield

l r0 sensor_800 Pressure
l r1 sensor_800 RatioCarbonDioxide
mul r1 r1 r0   # CO2 partial pressure

l r2 filtrationCO2_800 On
beqz r2 co2_off
sgt r3 r1 CO2_LOW
j co2_set
co2_off:
sgt r3 r1 CO2_HIGH
co2_set:
s filtrationCO2_800 On r3

l r4 sensor_800 RatioPollutant
sgt r5 r4 0
s filtrationPollutant_800 On r5

l r6 sensor_800 RatioMethane
sgt r7 r6 0
l r8 sensor_800 RatioHydrogen
sgt r9 r8 0
max r7 r7 r9
s filtrationMethaneH2_800 On r7

l r11 sensor_800 RatioNitrogen
mul r11 r11 r0   # N2 partial pressure

beqz r12 n2_off
sgt r13 r11 N2_LOW
j n2_set
n2_off:
sgt r13 r11 N2_HIGH
n2_set:
move r12 r13   # persist for next tick's hysteresis check - see comment above

# Pump runs whenever any one of the four triggers above is active
max r10 r3 r5
max r10 r10 r7
max r10 r10 r12
s recyclePump_800 On r10

j main
